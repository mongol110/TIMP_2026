# Спецификация требований TIMP_AES_AUDIO

## 1. Введение
Проект представляет собой клиент-серверное приложение, предназначенное для демонстрации
криптографических алгоритмов (AES-128-CBC, SHA-1), численного метода (метод Ньютона),
стеганографии в аудиофайлах (LSB в WAV), а также принципов сетевого взаимодействия
(мультиклиентский TCP-сервер, авторизация) и паттерна Singleton.

## 2. Функциональные требования
- F1: Сервер должен обрабатывать одновременные подключения нескольких клиентов
  (у каждого сокета свой буфер и auth-состояние, порт 34944).
- F2: Клиент должен предоставлять графический интерфейс пользователя (GUI) для ввода данных:
  вкладки Авторизация / AES / SHA1 / Ньютон / Аудио-стего, лог и таблица команд, флаг авторизации.
- F3: Должна поддерживаться аутентификация и регистрация пользователей
  (`REGISTER|login|pass`, `AUTH|login|pass`); без AUTH функциональные команды запрещены.
  Ролевая модель (guest/user/admin) и функции администратора НЕ реализованы.
- F4: Реализация алгоритмов:
  - AES-128-CBC шифрование/дешифрование (OpenSSL EVP, IV=0, ключ до 16 байт)
  - Хэширование SHA-1 вручную (FIPS 180-4, без библиотек)
  - Метод Ньютона для нахождения корня уравнения x³−x−2=0 (15 знаков)
  - Внедрение/извлечение сообщения в WAV (LSB, 1 бит на байт аудио после заголовка 44 байта)
- F5: Все запросы должны логироваться в базу данных (пользователь, команда, ответ;
  пароли маскируются, длинные base64 урезаются).

## 3. Нефункциональные требования
- NF1: Приложение должно быть написано на C++17 с использованием Qt6.
- NF2: База данных сервера и сетевой клиент должны быть реализованы
  с использованием паттерна Singleton (`DataBase::instance()`, `TcpClient::instance()`).
- NF3: Проект должен собираться с помощью CMake и qmake.
- NF4: Должна быть обеспечена возможность сборки и запуска сервера через Docker (docker-compose).
- NF5: Неизвестная команда и пустой запрос не должны ронять сервер (ответ `error`).

## 4. Требования к базе данных
- DB1: Использовать SQLite.
- DB2: Хранить пароли в виде хэшей SHA-1 от `login:pass` (ручная реализация SHA-1).
- DB3: Таблицы `users (login UNIQUE, pass_hash)` и `logs (user, command, result, timestamp)`.

## 5. Приёмка
- Register → Auth → SHA1/AES/NEWTON/AUDIO через сокет и через GUI.
- Два одновременных клиента не мешают друг другу.
- UnitTests: 4 теста зелёные (6 passed, 0 failed).
